# Android更新のiOS適用（アプリ内更新を除く）

## 追加・変更した機能

- 設定画面の「QRコードで接続」からCameraControllerのQRを読み取り、カメラ専用のAPI Keyを取得する。
- 接続URL・カメラID・API Keyを一組として保存する。以前の手入力設定は初回起動時に引き継ぐ。
- QR接続、手入力設定変更、再接続で、古いWebSocket・登録API・タイマー・コマンド完了通知を無効化する。
- カメラをOffererとする映像のみのWebRTC配信。視聴者ごとのPeerConnection、共通の映像ソース、H.264 Baseline系を使用する。
- 視聴者がいてWebRTCが接続できない状態が6秒続いたらJPEGへ切り替える。全視聴者が接続するか、接続できない視聴者が退出すると停止する。
- JPEGは長辺640px・品質30%。送信間隔は設定画面から変更する。
- 接続中のネットワーク種別を取得して状態報告へ含める。バッテリー表示は30%以下で黄色、10%以下で赤。
- LAN接続の権限説明とローカル接続用ATS設定を追加する。TLSはOS標準の検証を使用する。
- 更新確認、APK取得、アプリ更新の案内は追加しない。

## ビルドと自動テスト

Xcodeで`MirroringCamera.xcodeproj`を開き、共有スキーム`MirroringCamera`を使用する。
WebRTCのSwift Package（stasel/WebRTC 154.0.0）を初回に取得する。

```sh
xcodebuild -project MirroringCamera.xcodeproj -scheme MirroringCamera \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project MirroringCamera.xcodeproj -scheme MirroringCamera \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO test
```

シミュレーター名は手元の環境に合わせる。コマンドラインのXcodeが選択されていない場合は、
`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`をコマンドの前に付ける。

`Tests`はQR検証、ペアリングAPIの応答・エラー、既存設定移行、認証情報の一括保存、
URLのエンコード、JPEG切り替えの猶予・復帰・複数視聴者・解除、実際のWebRTC Offer生成、登録中の切断、重複接続、手動切断後の画面復帰を確認する。
GitHub Actionsでも端末向けビルドとシミュレーターのテストを実行する。

通常の起動ではこの設定を使用しない。

## 実機とCameraControllerで確認する項目

- 既存の手入力設定で接続し、切断後に画面へ戻っても意図せず再接続しない。
- QR接続で返却されたカメラIDと接続先を使う。別サーバーのQRへ切り替えても旧接続が復活しない。
- 無関係なQRは無視し、期限切れ・使用済み・無効なQRは理由を表示する。
- QR画面を閉じると読み取りを終了し、取得中に閉じた場合は遅れて届いた接続情報を適用しない。
- LAN権限の許可・拒否、HTTPのLAN接続、公開HTTPS接続を確認する。
- 管理画面1台・複数台で映像を表示し、退出・再入場・Wi-Fi切断と復帰を確認する。
- WebRTCを接続できなくしたとき、6秒後にJPEGが届き、接続復帰後にJPEGが停止する。
- 縦横の回転、回転ロック、解像度・FPS変更で映像の向きと比率を確認する。
- 配信しながら写真・動画・タイムラプスを操作し、保存、遠隔操作、ATEMのアクティブ表示を確認する。
- HDMI等の外部ディスプレイと配信・録画を同時に使い、表示と撮影を確認する。

QR画面は既存の映像フレームを表示し、VisionでQRを背景解析する。画面の開閉時にカメラセッションを再設定しない。
解析は最大毎秒5回・同時に1フレームとし、閉じた画面や一時停止前の解析結果は破棄する。
シミュレーターでは互換性のため従来のVision QR検出方式を使用する。実機では現行の検出方式を使用する。
録画・タイムラプス中はQRボタンを無効化する。
シミュレーターの自動テストではカメラ映像、録画保存、外部ディスプレイの実動作は検証できない。

## WebRTC接続復旧の修正（2026-10-15）

コード上で確認した問題と対策:

- ICE切断・失敗後の再交渉がなかった。10秒の猶予後にICE restart付きOfferを送り、接続できない間は10秒以上の間隔で再試行する。SDP交渉中のOfferは上書きせず、短時間の切断から自然復帰した場合は再試行を取り消す。
- 接続済み視聴者がいないと映像ソースへの供給を止めていた。購読中は接続準備・復旧中もフレームを供給する。
- 1人の接続成功が他の視聴者のJPEGフォールバックまで止めていた。未接続時間を視聴者ごとに保持する。
- 出力サイズを毎フレーム設定していた。サイズ変更時のみ設定し、出力寸法を偶数に揃える。
- SDPとICE候補の適用エラーをログへ記録する。

実機では、Wi-Fiの短時間切断と10秒以上の切断、複数視聴者のうち1台だけ接続不可、視聴者の退出後に再試行が止まることを確認する。受信側が同じsession_idの再OfferにAnswerを返すことも確認する。
現状のICE設定はGoogle STUNのみで、TURNサーバーはない。直接接続できないネットワーク向けのTURN導入には、運用サーバーと認証情報の配布仕様が必要。
Answerが届かずSDP交渉中のままの場合は、競合防止のためICE restartを重ねずJPEG配信を続ける。
カメラ実機とCameraControllerを接続した映像・ネットワーク切替の検証は未実施。

今回の修正の検証結果:

- 最終コードのiOS実機向け署名なしビルド成功。
- 同一ソースとWebRTCバイナリを使ったMac上のXCTest 10件が全件成功。候補を渡さずICE接続不可にしたPeerに対して、約10秒後に異なるICE ufragのOfferが生成されることを確認した。
- iOSシミュレーターはビルド後のテスト起動待ちから進まず中断。iOSでのテスト成功とは扱っていない。
